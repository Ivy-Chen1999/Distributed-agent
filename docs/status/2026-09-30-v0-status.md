## Results since the last report

- **v0.3 pooled over 6 runs per case** (baseline in brackets): case_01 coverage ≈0.70 (0.70),
  omissions ≈0.71 (0.83); case_02 coverage ≈0.69 (0.57), omissions ≈0.83 (0.50). Net better, the
  gain is on case_02. Identical runs move single-case coverage by ~0.1, so 3 repetitions only
  resolve differences above ~0.1.
- **Jev fiscal fix**: with the old question ("fiscal specialist") Jev scored fiscal 0.19–0.49
  where it was useful 5/6 times. With domain glosses: 0.83–0.91 on the real cases, 0.45 on a
  governance-only control, 0.89 on a fees-only control. Latest calibration (18 decisions): Brier
  0.021 — but every decision was "relevant" (base rate 1.00), so this does not show calibration
  yet. Scenarios where an expert is truly irrelevant are needed (v1, with the full dataset).
- Bugs found by the e2e suite and fixed: Manrope ligature turning "(c)" into ©, misleading 502
  message in Ask, Settings crash on a null source path, overview showing error + empty state,
  status chip "No runs yet" when the list failed, keep-alive reset under 5 s polling.

## Hardening after three review rounds

Job runner: queue slots reserved before any await, heartbeats only for runs still executing, failed
runs carry an `error_kind`. Ask: runs on the run's own synthesis backend, max 4 in flight, 120 s
timeout. Postgres writes strip U+0000. Claude Code self-check fails closed on every path. Console:
request timeouts, poll backoff, accessible contrast / focus / scroll regions
(`docs/ui/README.md`). Every data route is tested to require the token.
